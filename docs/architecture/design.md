# Domain, architecture and decisions

The [original 132-section specification](../product/original-prompt.md) supplies authoritative requirement IDs. [The feature matrix](../product/feature-matrix.md) maps implementation, permissions, privacy, tests, documentation and observability. The [81-role catalog](../product/roles.md) supplies review perspectives; these are applied by the implementer, without claiming independent audits.

Accounts authenticate; immutable identities carry profiles. Explicit memberships delegate actions for nine identity types. Historical handles remain reserved. Personas override base claims without copying authority. Claims retain registered types, locale, provenance, freshness, selected source and disclosure policy. Enterprise assertions retain issuer/recipient authority separately: recipient acceptance starts private and publication requires another deliberate action.

Browser -> same-origin reverse proxy -> Next.js and modular NestJS -> PostgreSQL. Separate delivery, worker and scheduler processes share domain primitives. PostgreSQL is authoritative for ownership, policy, consent and the transactional outbox. Redis supplies atomic throttling, circuit breakers and bounded delivery projections. Private S3 stores quarantined uploads, immutable processed objects, private exports and encrypted evidence. No proprietary cloud is required for core operation.

Important mutations lock current authority and write audit/outbox records in the same transaction. Workers claim jobs using SKIP LOCKED, lease tokens and heartbeats; retries preserve webhook delivery IDs. They recheck current consent, issuer, membership, state and deletion before side effects. Scheduler ticks use advisory locking and deterministic outbox IDs.

## Decisions

| ADR | Decision and reason                                                                                                                                                                                                                                              |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 001 | Modular monolith with separate operational processes; preserve domain transactions while scaling delivery and workers independently.                                                                                                                             |
| 002 | Parameterized PostgreSQL queries and append-only SQL migrations; invariants and concurrency locks stay explicit.                                                                                                                                                 |
| 003 | One policy engine before serialization; persona authority ranks before disclosure. Dynamic profiles and revocable uploaded assets use no-store.                                                                                                                  |
| 004 | Argon2id, verified email, opaque revocable sessions and reviewed WebAuthn/TOTP libraries. OAuth authorization code uses S256 PKCE and exact registered redirects.                                                                                                |
| 005 | ASCII handles limit confusables; Unicode display/native/transliterated names and localized content remain supported. Historical handles cannot be recycled.                                                                                                      |
| 006 | PostgreSQL outbox is durable truth; Redis/cache loss cannot erase committed work.                                                                                                                                                                                |
| 007 | Bounded raster decoding and complete re-encoding strip metadata and reject active/malformed uploads. Generated SVG uses original fixed safe shapes.                                                                                                              |
| 008 | The requested Docker/PostgreSQL/Redis platform takes precedence over an incompatible Sites runtime.                                                                                                                                                              |
| 009 | Protocols advertise documented subsets. Orbit federation v1 is a custom signed peer protocol; VC/DID and OAuth boundaries are explicit in the protocol guide. OIDC and GraphQL are disabled.                                                                     |
| 010 | Audiences derive from current memberships and mutually confirmed relationships. Anonymous SEO metadata is separate from personalized page content.                                                                                                               |
| 011 | A Redis generation and writer fence protect minimal delivery projections. Sensitive writes invalidate before SQL and after commit/rollback; pending writes force authoritative reads. A crashed writer leaves the fence closed until maintenance reconciliation. |
| 012 | Identity/account merge requires proof of both owners, a preview, locks and a recorded provenance event. Source IDs, handles and history survive; imported/private data never silently becomes public. Source sessions and grants are revoked as required.        |
| 013 | Federation approval pins peer keys; audience, expiry, sequence, replay and current blocking are checked before remote caching. Update/Delete/Move are distinct operations.                                                                                       |
| 014 | Full backups combine PostgreSQL and private S3 in an authenticated encrypted envelope. Restore verifies authentication and every checksum before creating isolated targets.                                                                                      |

Versioned REST uses shared strict input contracts, typed public output contracts, safe errors and request IDs. Dashboard changes save deliberately. Saved previews use the same PUBLIC, SEARCH, APPLICATION and OWNER policy projections as actual consumers. Editors support structured block inputs, keyboard/drag ordering, history comparison and private restore. Account locale and IANA timezone drive dates and direction; public content carries its locale and direction.

Milestones and role gates are recorded in the refined prompt. Runtime evidence lives in the release report and ignored report artifacts. Public deployment, external provider credentials and certificate/SMTP environment inputs remain operator configuration, with implemented boundaries and local rehearsals.
