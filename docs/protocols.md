# Protocol and integration contracts

OAuth 2.0 uses authorization code and rotating refresh tokens, exact registered redirects and mandatory S256 PKCE. Public clients send client_id; confidential clients authenticate with HTTP Basic. Token/revocation requests are strict single-valued form bodies. Authorization grants are bound to the signed-in account, selected identity/persona, current owner membership, fields, scopes and expiry. Code/refresh replay revokes the affected family. OAuth metadata is /.well-known/oauth-authorization-server. Credentials use credentials.read plus explicit credential:vcr_ID fields; GET /api/v1/oauth/credentials discloses only those current holder credentials. Native ic_ consent tokens use /api/v1/application/profile and /api/v1/application/credentials; ik_ identifies an application and cannot read private identity data. OAuth and native tokens are distinct. OIDC is disabled.

DIDs support the did:web pure JSON Ed25519/JWK subset. Local identity documents are opt-in at /api/v1/dids/ID/did.json. External resolution requires bounded HTTPS/DNS validation and a nonce-bound signature challenge; no universal identity-verification label follows from associating a DID. Active keys sign, retired keys verify, and revoked keys stop credential verification. VC 2.0 credentials are direct JSON JOSE vc+jwt objects with the W3C context, issuer, native holder URL, validity interval and a custom live status method. /schemas/IdentityAssertionCredential, /schemas/IdentityCredentialStatus and /schemas/claim describe the custom semantics. This implementation does not advertise JSON-LD proof suites, BitstringStatusList, SD-JWT or remote credential-issuer verification. Selective disclosure means explicit selection of whole credentials and separately governed profile fields.

Orbit federation v1 uses signed ActivityStreams-shaped Update/Delete/Move activities carried in EdDSA JOSE messages. It is a documented custom protocol, not ActivityPub. Operators approve peers using out-of-band discovery-document fingerprints. Messages bind issuer, pinned key, audience, timestamp, expiry, unique message ID and monotonic sequence. Only current PUBLIC machine-enabled fields are projected. Delete, blocked peers and local visibility/state changes remove remote content. Ordinary remote profile caches expire after 24 hours; migration aliases persist but require both source and destination nodes to remain approved.

Migration requires an account-bound source nonce and a destination-owner step-up acceptance signed by that destination node. Completion rechecks current source ownership, both approved nodes, exact target, source, nonce, audience and signature. The source becomes TRANSFERRED/private and its grants, providers and domains are revoked. Export/import is an explicit reviewed step; migration does not silently transfer private data. A receiving node verifies both the source Move signature and the separate destination acceptance.

Enterprise assertions preserve immutable issuer authority and distinguish issuer management from recipient ownership. HR-capable organization managers issue bounded assertions; recipients accept with an explicit policy, dispute or decline to publish. Issuer revocation removes the assertion and corresponding credential without deleting the recipient identity.

Webhooks use HMAC-SHA256 over timestamp + "." + rawBody, plus a stable delivery ID. Receivers compare signatures in constant time, reject timestamps outside five minutes and deduplicate delivery IDs. Event bodies contain event ID, type, identity ID and occurrence time; audit details and private field values are excluded. Durable retries are bounded, current application/consent ownership is checked before delivery, and application owners can inspect sanitized delivery metadata, enable/disable endpoints, rotate secrets, send test events and explicitly replay deliveries. Replays retain the delivery ID and recheck current authorization.

GitHub is the installed external provider adapter. It uses immutable provider IDs, PKCE, short-lived single-use state, encrypted tokens, reviewed per-field private imports and opt-in synchronization. Other providers can implement the adapter contract; they are not advertised as available. Website JSON-LD imports and reciprocal rel=me/feed verification use bounded SSRF-protected HTTPS transport.
