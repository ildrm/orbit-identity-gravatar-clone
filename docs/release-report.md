# Orbit 1.0.0 implementation and release evidence

Recorded 2026-10-03 in the local Windows/Docker Desktop environment.

**The enabled implementation is complete and its local release gates pass.** OAuth, enterprise assertions, proved account/identity merging, signed federation/migration and the other enabled requirements are implemented. The [132-section ledger](product/feature-matrix.md) records implementation boundaries and evidence; AI imagery, OIDC and GraphQL are optional and disabled. Production deployment still needs the operator's real domains, SMTP, protected credentials and infrastructure.

## Delivered product

The original prompt is preserved in [product/original-prompt.md](product/original-prompt.md). The [optimized prompt](product/implementation-prompt.md) adds explicit invariants, dependencies, acceptance evidence and responsibilities for all [81 extracted roles](product/roles.md). Specification checks retain every original numbered section and role.

The platform includes verified password/passkey/TOTP authentication and account lifecycle; stable identity IDs, reserved handle history, nine identity types, localized typed claims, provenance, personas and separate disclosure channels; structured blocks, themes, saved audience previews and keyboard ordering; public SSR/search/machine/vCard/WebFinger/QR; quarantined private media, immutable edits, responsive variants and scheduled/default/persona/application/domain selection.

Current account and membership authority governs organization roles, recipient-controlled enterprise assertions, native grants and OAuth PKCE consent. Private avatar routes require current identity.read and avatar.read authority, use bearer headers, recheck revocation after object reads and return no-store responses.

Private VC/DID proof and key rotation, approved signed federation and independently signed migration, custom-domain proof/TLS authorization, bounded GitHub import/sync, reciprocal website verification, opt-in aggregate analytics, notifications/contact/moderation/appeals, revision restore, complete JSON/media archives, reviewed private import, proved merging and digital legacy are implemented. SDKs, CLI and the WordPress plugin are distributable under the preserved GPL license.

[Protocol contracts](protocols.md) state the exact supported subsets. Orbit federation v1 is custom; VC/DID support does not imply every proof suite or standards certification. GitHub is the installed external provider adapter. UI language remains English, with localized data/dates, IANA timezone preferences and RTL layout.

## Measured workload limits

The disposable benchmark uses actual production API/delivery/worker code, PostgreSQL, Redis, private S3, SMTP and a trusted HTTPS webhook receiver. It records percentiles, error rates, queue state and resource metadata. Generated and processed avatars had p95 230 ms; public profiles 193 ms; resolution 67 ms; search 33 ms; consented reads 42 ms; transactional writes 56 ms; Argon2 login 712 ms; HTTPS webhook completion 585 ms; portable JSON/media exports 1,251 ms.

These are small workstation samples, measured while other local verification ran. Their p99 values are sample maxima. They establish the declared local budgets, not public CDN capacity or a production SLA. Fault tests use owned disposable services on an internal Docker network with loopback forwarding; no external webhook message is sent.

## Defects fixed during verification

The final checks found and corrected actual defects: private-avatar authorization and expiry/revocation boundaries; claim/block actor metadata and atomic ordering/restore; cache invalidation during concurrent or interrupted sensitive writes; paused PostgreSQL readiness deadlines; bounded S3/outbound/provider calls; provider failure metadata and circuit behavior; initial private-storage write readiness; responsive header/media handling; mobile touch-target sizing; block-save/form-reset and initial claim-load races that could erase fast edits.

Accessibility rules and production quotas stayed enabled. Browser tests exercise real WebAuthn verification through a virtual authenticator. They do not establish every physical authenticator's compatibility or replace manual assistive-technology review. WordPress uses a controlled profile fixture for rendering/escaping checks; live external HTTPS success is not claimed.

## Deployment and evidence boundaries

The running app is [http://localhost:8080](http://localhost:8080), moderator app [http://localhost:8081](http://localhost:8081), development mail [http://localhost:8025](http://localhost:8025), and [OpenAPI](http://localhost:8080/api/v1/openapi.json). No user passwords are seeded.

The [release manifest](operations/release-manifest.json), [upgrade procedure](operations/upgrade.md), [deployment guide](operations/deployment.md), [recovery runbook](operations/recovery.md) and [monitoring guide](operations/monitoring.md) provide the release artifacts and operating steps. Named data volumes and the original GPL-2.0 license are preserved.

Public DNS/ACME, production SMTP deliverability, live GitHub authorization, offsite backup/PITR services, organization-trusted signing, registry publication and remote CI need operator-controlled endpoints, credentials and identities. They have not been performed from this workspace. The CI workflow contains the behavioral and release gates but has not been pushed or executed remotely. Role reviews are implementer perspectives, not independent security/privacy/accessibility certification. Image scans cover API, web, admin, PostgreSQL, Redis, storage, proxy and TLS; development Mailpit, optional Prometheus and the host OS are outside that scan scope.
