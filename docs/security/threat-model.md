# Threat model

Assets include account/session credentials, identity authority, private claims, provider/MFA/webhook/DID secrets, media, credentials, legacy evidence, exports, recipient addresses, audit records and backups. Trust boundaries separate browser/proxy/API, accounts/identity memberships, app grants, issuer/recipient authority, public/private channels, database/cache/storage, side-effect workers, federation peers and operator/moderator control.

| Threat                            | Control                                                                                                              | Behavioral evidence and limits                                                                                   |
| --------------------------------- | -------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| IDOR/escalation                   | Action-specific current membership locks; explicit owner/issuer/recipient/moderator boundaries                       | Eight-role allow/deny matrix and cross-account operational regressions.                                          |
| Privacy leakage                   | Authority-first SQL projection, typed policy, scope/field/persona intersection                                       | Private canaries across HTML/JSON/search/machine/media/OAuth/export/federation.                                  |
| Account takeover                  | Argon2id, verified email, digest challenges, generic recovery, revocable sessions                                    | Real SMTP codes, account-bound email changes, password/session revocation and MFA replay checks.                 |
| MFA/passkey takeover              | Reviewed WebAuthn verification, recent step-up, encrypted TOTP, single-use backup codes                              | Actual virtual-authenticator Chrome flow and backup rotation/disable tests.                                      |
| CSRF/CORS/session theft           | Exact configured mutation Origin, HttpOnly/SameSite, Secure HTTPS production cookie                                  | Origin/CORS denials and local trusted TLS rehearsal; public host inputs remain deployment configuration.         |
| SQL/XSS                           | Parameterized SQL, strict bounded schemas, React/WordPress escaping, safe HTTPS links                                | Actual malformed input, SQL constraints, browser WCAG and WordPress runtime checks.                              |
| SSRF/rebinding/slow transport     | All-address public validation, pinned DNS, no redirect, lookup/socket/total deadlines and byte limits                | Address tests, private target denials, real trusted HTTPS receiver and provider network failure.                 |
| Media attacks                     | Exact signed size, HEAD verification, raster/pixel/frame bounds, full re-encoding and quarantine                     | Real rejection/edit/variant/publication/private-consent tests.                                                   |
| Cache stale authority             | Minimal Redis generation/writer fence; bounded temporal validity and reconnect rotation                              | Warm hit/no loader, overlapping writes, committed invalidation, expiry, corruption and real disconnect recovery. |
| OAuth confusion/replay            | Exact redirect and issuer/state, S256 for public/confidential clients, one-time codes, rotating refresh families     | Actual form/PKCE/authentication/deny/replay/refresh/revoke and explicit disclosure regressions.                  |
| Credential impersonation          | Private issuance with current issuer/assertion/key/status checks; separate recipient acceptance                      | Cryptographic EdDSA verification, key rotation/revocation and selected holder grant disclosure.                  |
| Federation spoof/replay           | Explicit approved peer pin, signed audience/expiry/sequence, protocol version and dedupe                             | Signed Update/Delete/Move, replay denial, blocking purge and independent destination signature.                  |
| Unsafe merge/import               | Proof of both owners, consequence preview, transactional locks, private import/restore and provenance                | Identity/account merge, preserved aliases/history and source authentication revocation.                          |
| Domain takeover                   | Fresh DNS/well-known/routing proof, expiry/revalidation, removal and certificate ask gate                            | Local Caddy TLS allow/deny/removal rehearsal; real public DNS/ACME still needs deployment inputs.                |
| Job resurrection/duplicate effect | Current-state rechecks, renewable lease/token, outbox, stable delivery IDs                                           | Worker SIGKILL/reclaim, webhook rejection/replay and receiver side-effect dedupe.                                |
| Legacy abuse                      | Accepted custodian has no present editing rights; encrypted evidence, 30-day wait, independent approvals, owner veto | Waiting/reviewer/veto/terminal-state regressions.                                                                |
| Contact/moderation abuse          | Opt-in verified sender, hidden recipient, explicit reply sharing, quota/blocking and independent appeals             | Actual relay/inbox/block/appeal tests.                                                                           |
| Rate bypass/outage                | Atomic Redis and one trusted direct proxy; fail closed                                                               | Redis outage/readiness/recovery and unchanged quota pacing in tests.                                             |
| Secrets/supply chain              | Identified authenticated encryption, credential digests, sanitized error codes, build exclusions and pins            | Rotation rehearsal and Gitleaks/npm/SBOM/Trivy gates and exact scanned-image matching.                           |
| Data loss                         | Consistent encrypted PostgreSQL + S3 envelope; authenticate/checksum before isolated restore                         | Actual private object/hash/migration/tamper/primary-target refusal rehearsal.                                    |

Operators with database and key access remain trusted. Previously disclosed/downloaded data cannot be recalled. Production DNS, SMTP, offsite/PITR, federation partners and alert routing need protected deployment configuration. Local fixtures and scans establish bounded behavior; they do not imply independent penetration testing, universal protocol conformance, legal certification or global capacity.
